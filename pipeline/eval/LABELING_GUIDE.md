# 골든셋 라벨링 가이드

분류기(키워드·hybrid·Gemini)를 평가할 **정답 라벨**을 사람이 다는 기준. 라벨은 반드시 사람이 직접 단다 —
LLM으로 정답을 채우면 검증 대상이 자기 자신을 채점하게 된다.

- 대상: `golden_v1.csv`의 300건 (게시판×월 층화 추출, 시드 고정 — `golden_v1.meta.json`)
- 도구: `cd pipeline && uv run python -m eval.label` (자동 저장, 언제든 `q`로 끄고 이어하기)
- 예상 소요: 건당 5~10초, 총 30~50분

## 원칙

1. **화면에 보이는 정보로만 판단한다.** 원문 링크를 찾아 열거나 댓글을 보지 않는다.
   현재 크롤러는 목록 페이지의 **제목만** 수집하므로(본문은 비어 있음) 분류기도 제목만 본다.
   같은 입력으로 판단해야 "분류기가 사람만큼 읽는가"를 공정하게 잴 수 있다.
2. **분류기 예측은 보지 않는다.** 도구는 일부러 예측값을 숨긴다(앵커링 방지).
3. **글쓴이가 드러낸 감정**에 라벨을 단다. 대상이 게임·운영사·다른 유저·직업 무엇이든 상관없다.
   대시보드는 "커뮤니티 분위기"를 보여주는 것이 목적이기 때문.
4. **확신이 없으면 가장 그럴듯한 라벨을 고르고 `?`로 표시한다.** 건너뛰기(`s`)는 라벨 자체가
   성립하지 않는 글(아래 5번)에만 쓴다. `?` 표시 글은 평가 때 따로 집계해 지표 민감도를 본다.
5. 말머리(`[잡담]`, `[일반]`)와 댓글 수(`[10]`)는 무시한다.

## 라벨 정의 (현재 분류기 프롬프트 기준 — `src/processors/classifier.py`)

| 키 | 라벨 | 정의 | 대표 신호 |
|---|---|---|---|
| `1` | **positive** | 칭찬·기쁨·성취·감사·공략/팁 공유·상향 환영·이벤트 호평 | 졸업, 드디어, 득템, 꿀팁 공유, 감사, 재밌다, 혜자 |
| `2` | **negative** | 불만·비판·항의·탓·욕설·포기/이탈·환불·버그 신고·너프 요구·운영 비판·유저 간 비난 | 접는다, 망겜, 답없다, 버그 언제 고침, ㅡㅡ, 현타, 운영 탓 |
| `3` | **neutral** | 순수한 질문·정보 요청·단순 사실 전달·감정 없는 관찰 | ~나요?, 몇 시, 어디서, 추천 부탁, 공지 요약 |
| `s` | (skip) | 라벨이 성립하지 않음: 스팸 필터를 빠져나온 광고·거래글, 의미 없는 문자열, 제목이 잘려 판독 불가 | |
| `?` | (표시) | 위 라벨과 함께 쓰는 "애매함" 플래그 | |

> 정의상 주의: 현재 프롬프트는 **공략·팁 공유를 positive**로, **버그 신고를 negative**로 본다.
> 일반적인 감성 분석과 다를 수 있지만, 분류기를 "설계 의도대로 동작하는가"로 평가하기 위해 이 기준을 따른다.

## 애매한 경우 판단 기준

### A. 질문 형식 vs 실제 감정
판단 질문: **"답을 몰라서 묻는가, 불만을 표현하려고 묻는가?"**

| 예시 (가상) | 라벨 | 이유 |
|---|---|---|
| 정령성 스킬 순서 어떻게 찍나요? | neutral | 정보 요청 |
| 이거 왜 자꾸 튕기나요?? | **negative** | 문제 상황에 대한 불만 — 물음표는 형식일 뿐 |
| 패치 언제까지 이렇게 방치할 건가요 | **negative** | 수사적 질문, 운영 비판 |
| 다들 이번 이벤트 보상 받으셨나요? ㅎㅎ | neutral | 가벼운 확인 질문 (만족 표현이 뚜렷하면 positive + `?`) |

> 이 구분이 hybrid v1(물음표 → 무조건 neutral)과 v2(키워드 우선)의 핵심 차이다. 물음표에 끌려가지 말 것.

### B. 반어·비꼼
**문자 그대로가 아니라 의도된 의미**로 라벨링한다.

| 예시 (가상) | 라벨 |
|---|---|
| 와 점검 또 연장 진짜 갓겜이네 ㅋㅋ | negative |
| 역시 믿고 보는 운영 ㅋㅋㅋ (사고 직후 맥락) | negative |
| 이 가격에 이 구성이면 혜자 맞음 | positive (진심 칭찬) |

신호: 긍정 단어 + 부정적 사건(점검·버그·과금), 과장된 `ㅋㅋ`, `ㅡㅡ`, "역시", "참 잘~". 맥락 없이 판단이 안 서면 `?`.

### C. 긍정·부정 혼재
**글쓴이가 마지막에 남기는 평가(결론)** 를 따른다. 결론이 없으면 비중이 큰 쪽.

| 예시 (가상) | 라벨 |
|---|---|
| 그래픽은 좋은데 과금 유도가 너무 심함 | negative (결론이 불만) |
| 초반엔 답답했는데 세팅 맞추니까 재밌네요 | positive |
| 장단점 정리해봄 (평가 없이 나열) | neutral + `?` |

### D. 정보·공략·후기
| 유형 | 라벨 |
|---|---|
| 공략·팁을 **나눠 주는** 글 ("~하는 법 정리했습니다") | positive (프롬프트 정의) |
| 단순 사실 전달 (패치 내용 요약, 일정 공유) | neutral |
| 후기 — 만족/불만이 드러남 | 해당 감정 |
| 수치·스펙 공유 ("목표 전투력 달성") | 성취감이 보이면 positive, 단순 보고면 neutral |

### E. 게임 은어·커뮤니티 표현
| 표현 | 보통 의미 | 라벨 경향 |
|---|---|---|
| 졸업, 득템, 클리어, 뚫었다 | 성취 | positive |
| 혜자, 개꿀, 꿀잼, 갓겜 | 호평 (반어 주의 → B) | positive |
| 창렬, 망겜, 나락, 노답, 현타 | 혹평 | negative |
| 접음/접는다/탈주 | 이탈 선언 | negative |
| 너프 해줘 / 하향 시급 | 다른 직업에 대한 불만 | negative |
| 상향 감사 / 드디어 버프 | 환영 | positive |
| 사기캐 | 남의 직업이면 불만(negative), 내 직업 자랑이면 positive | 맥락 |
| 숙제 | 반복 콘텐츠 피로감 — 불만 어조면 negative, 단순 언급이면 neutral | 맥락 |
| ㅋㅋ | 웃음·조롱 둘 다 — 단독으로는 신호 아님 | — |
| ㅠㅠ | 기쁨(감격)·슬픔 둘 다 — 앞 내용으로 판단 | — |
| 똥손, 망했다(자기 실수) | 자조 — 게임 불만이 아니면 약한 negative, 애매하면 `?` | 맥락 |

### F. 감정 신호가 전혀 없는 글
잡담·근황·질문 아닌 단순 진술("오늘 첫 접속") → **neutral**. 억지로 감정을 찾지 않는다.

### G. 게임과 무관한 글
게임 외 잡담도 대시보드 집계에 들어가므로 **드러난 감정대로** 라벨링한다(스킵하지 않음).
광고·거래·도배처럼 스팸 필터가 놓친 글만 `s`.

## 품질 관리

- 한 번에 100건 정도씩 끊어서 한다(피로하면 neutral 쏠림이 생긴다).
- 끝나면 `?` 표시 글만 다시 훑어 기준이 일관됐는지 확인한다.
- (선택) 1주일 뒤 무작위 30건을 다시 라벨링해 **자기 일치도**(Cohen's κ)를 잰다 — 라벨러가 1명이라는
  한계를 정량화하는 최소한의 방법.
- 기준을 바꿔야 하면 이 문서를 먼저 고치고 커밋한 뒤, 영향받는 라벨을 다시 확인한다.
